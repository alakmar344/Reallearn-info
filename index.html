What RealLearn Is

A guided-learning platform for students who want structured understanding.

RealLearn transforms questions into intentional journeys — foundation, mechanism, and real-world relevance. Every lesson shapes itself to your level and language.

The Problem

One-shot answers don't teach — they forget.

Traditional AI gives shallow responses that don't match your level or connect to today. Students need guided progression, verified comprehension, and living knowledge.

How It Works

Every session follows a clear path — from question to lasting understanding:

  1. Ask. A learner enters a question — anything that sparks curiosity. There are no wrong questions.
  2. Configure. The learner selects their language and depth. reallearn meets them where they are.
  3. Request. The frontend calls /api/generate-lesson — the engine awakens.
  4. Ground. The backend fetches real-world context — current events, recent developments, live data. Theory meets today.
  5. Generate. The engine composes a structured 3-stage journey, calibrated precisely to level and language.
  6. Validate. The backend runs a 5-stage resilience pipeline — if the model stumbles, the repair layer catches it.
  7. Render. The frontend presents all 3 stages, sources, and quizzes — a learning experience, not a wall of text.
  8. Gate. Each quiz must be passed to unlock the next stage. Comprehension is not assumed — it's verified.
  9. Continue. The learner completes takeaways and loops deeper. Every answer opens a door to the next question.

Feature Deep Dive

Nothing is decorative. Everything is deliberate. Every feature closes a specific gap in how learners actually absorb, retain, and apply knowledge.

  • 3-Part Unlockable Journey — Foundation → Mechanism → Real World Now. An arc from "what is it?" to "why does it matter today?"
  • Quiz-Gated Progression — 2 MCQs per stage, 4 options each. You don't advance until understanding is demonstrated. Active recall, in its purest form.
  • 8-Language Native Generation — English, Hindi, Gujarati, Tamil, Bengali, Marathi, Telugu, Kannada. Not translated — natively conceived in the learner's own language.
  • Adaptive Depth Calibration — Three levels with distinct vocabulary, complexity, and conceptual scaffolding. The lesson reshapes itself around the learner.
  • Real-World Context Integration — Serper-powered current event anchoring turns abstract theory into living knowledge that breathes with the present.
  • SSE Streaming with Heartbeat — Real-time server-sent events with keep-alive pings. The learner sees progress unfolding, not a blank screen.
  • Output Resilience Layer — Multi-stage repair and validation ensure smooth lessons every time.
  • Follow-Up Learning Loop — Every answer opens a door. Learners continue their journey iteratively, building depth with each question.
  • Session-Persisted State — Progress survives refreshes. The learning journey respects the learner's time, attention, and investment.

Node.js, Express, SSE streaming. AI engine for lessons. Validation layer for reliability.

Architecture & Deployment

A clean two-service architecture designed for reliability and performance.

  • frontend/ → Next.js on Vercel — fast, globally distributed frontend
  • backend/ → Express API → reliable backend for lesson generation
  • Core endpoint: POST /api/generate-lesson — creates your learning journey
  • Health check: GET /health — monitors service status

API & Streaming

Environment Variables

Core configuration for backend services and frontend connection:

Frontend

  • NEXT_PUBLIC_BACKEND_URL — Backend service URL
  • NEXT_PUBLIC_STREAM_IDLE_TIMEOUT_MS — SSE timeout setting

Backend — Core

  • API_KEY — AI service API key
  • MODEL — Model identifier for lesson generation
  • SERPER_API_KEY — API key for real-world context
  • FRONTEND_ORIGIN — Allowed CORS origin
  • PORT — Server port (default: 10000)

Backend — Reliability

  • MAX_RETRIES — Retry attempts for failed requests (default: 2)
  • RETRY_DELAY_MS — Initial retry delay (default: 700ms)
  • MAX_RETRY_DELAY_MS — Retry delay cap (default: 5000ms)
  • TIMEOUT_CIRCUIT_FAILURE_THRESHOLD — Failures before circuit opens (default: 5)
  • TIMEOUT_CIRCUIT_COOLDOWN_MS — Circuit cooldown period (default: 60000ms)

Backend — Operational

  • MAX_CONCURRENT_LESSON_REQUESTS — Concurrency limit (default: 3)
  • LESSON_FAILURE_ALERT_THRESHOLD — Failure count for alerting (default: 5)
  • SSE_HEARTBEAT_INTERVAL_MS — Heartbeat interval (default: 15000ms)
